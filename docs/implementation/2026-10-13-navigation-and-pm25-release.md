# ChiangMaiEyes: เมนูตามงานของผู้ใช้และซ่อมข้อมูล PM2.5

13 ตุลาคม 2026 · ต่อจาก [ภูมิประเทศ](2026-10-13-terrain-release.md)

## สิ่งที่ผู้ใช้จะเห็น

เมนูหลักลดจาก 7 เป็น 4 โดยคงฟังก์ชันไว้ในกลุ่มงาน:

| เมนู | อยู่ในหน้านี้ |
|---|---|
| สถานการณ์ | แผนที่ 2D, เปิดภูเขา 3D, กล้องสาธารณะ, ฝุ่น/ลม/จุดดาวเทียม |
| วิเคราะห์ | สรุปย้อนหลัง, สถิติละเอียดที่กดเปิดเพิ่ม, ข้อมูลในพื้นที่, ภูมิประเทศ, GFS/คลัง GFS, สร้างรายงาน |
| ชุมชน | ป่าของฉัน, ติดตามและประสานเหตุ, การแจ้งเตือน, ซ้อมใช้งาน, ตรวจคำขอตามสิทธิ์เดิม |
| คู่มือ | เว็บคืออะไร, เริ่มใช้ 4 ขั้นตอน, สมัคร/อีเมล, อ่านข้อมูลขาด, วิธีคำนวณ/พยากรณ์, references |

คู่มือไม่มีตัวเลือกป่า คลังย้อนหลัง กล้อง หรือแบบฟอร์มงานผู้ดูแล ข้อมูลเหล่านี้อยู่ในกลุ่มที่ใช้ทำงานจริง คู่มือเริ่มด้วยเลือกพื้นที่ → กดหมุดและอ่านเวลา → ดูฝุ่น/ลม → ตรวจสอบและติดตามเรื่อง

หน้าแบบจำลองการระบายอากาศและสถิติเฉพาะทางพับไว้ก่อน ส่วนรายงานปิดกลับหน้าวิเคราะห์ แผนที่ 3D กับกล้องยังเลือกเมนูสถานการณ์ และการเปลี่ยนแท็บภายในชุมชนยังเลือกเมนูชุมชน ปุ่มที่เปิดรายละเอียดภูมิประเทศจากหมุดเปิด “วิเคราะห์ → ข้อมูลในพื้นที่” แทนคู่มือ

ใช้ Impeccable (product/distill) คงธีมและ animation ของเว็บที่ผู้ใช้เลือก ลดขั้นตอนและข้อมูลที่แสดงพร้อมกัน ไม่เปลี่ยนบทบาทหรือเปิดข้อมูลส่วนตัวเพิ่ม

## PM2.5 หายเพราะอะไร

ก่อนแก้ API production คืน `current_pm25=null`, ไม่มีสถานีความเข้มข้น และมี AQI 61 สถานีจากแหล่งสำรอง AQI เหล่านี้ไม่ใช่ PM2.5 หน่วย µg/m³

ตรวจต้นทาง Air4Thai โดยตรง:

- Windows อ่าน HTTPS และได้ข้อมูลเชียงใหม่ 2 สถานี
- HTTPX/Python เดิมล้มเหลวด้วย `CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate`
- ตรวจ chain ที่ Windows ยืนยันแล้ว พบ Let's Encrypt YR1 → Root YR ที่ cross-sign โดย ISRG Root X1
- เพิ่มใบรับรอง issuer ที่ดาวน์โหลดจาก [Let's Encrypt](https://letsencrypt.org/certificates/) เฉพาะ context ของ Air4Thai คง `CERT_REQUIRED` และ hostname validation ปิด partial-chain trust ไม่มีการใช้ `verify=False`
- HTTPX อ่านต้นทางได้ HTTP 200 และ staged API บน Vercel อ่านได้ HTTP 200 เช่นกัน
- ตรวจเว็บหลักหลังปล่อย backend: เวลาแหล่งข้อมูล **13 ต.ค. 10:00 ICT**, `CM-35T` **16.4 µg/m³**, `CM-36T` **13.5 µg/m³**, API สรุป **14.9 µg/m³** / **2 สถานี** จาก Air4Thai PCD

ตัวเลขนี้เป็นผลจากต้นทางและจำนวนสถานีที่ตรวจตอนนั้น ไม่ใช่ค่าทุกชุมชนหรือการรับรองความแม่นยำภาคสนาม SHA-256 และแหล่ง issuer อยู่ใน `backend/app/data/tls/README.md` ต้องตรวจ issuer rotation/expiry หากต้นทางเปลี่ยน certificate chain ในอนาคต

แก้เพิ่มเติม: ค่าเฉลี่ยใต้กราฟใช้ข้อมูลชุดที่วาดกราฟ ไม่ถูกค่าจากสถานีมาทับเมื่อกราฟเป็น CAMS; เอาสูตร AQI แบบ ad-hoc และเส้นอ้างอิง 55 ที่ไม่ตรง caption เดิมออก ไม่สร้างดัชนีหรือความเข้มข้นแทนแหล่งที่ขาด

## วิธีและ references ในคู่มือ

อธิบายการนับรายการตรวจพบ, ค่าเฉลี่ยสถานี, slope Horn 3×3/UTM 47N/DSM, ดัชนีอากาศแห้งทดลอง, CAMS, GFS HPBL/PBL/VRATE และการที่ยังไม่มีผลไฟลามสอบเทียบ พร้อมลิงก์ต้นทาง 13 แหล่ง รวม Air4Thai และ [CAMS ผ่าน Open-Meteo](https://open-meteo.com/en/docs/air-quality-api) ซึ่งเพิ่มให้แยกจาก AQICN และอากาศปกติ

แก้ลิงก์อ้างอิง GIBS ไป [เอกสาร NASA GIBS](https://nasa-gibs.github.io/gibs-api-docs/) สูตรของเว็บแยกจากข้อมูลผู้เผยแพร่ ไม่อ้างว่าผู้เผยแพร่รับรองผลคำนวณ

## ตามแผนยังเหลืออะไร

อิง [แผนชุด 3–7](2026-10-10-next-work-plan.md) และผล release หลังจากแผนนั้น ไม่ถือว่ารายการในเอกสารเก่าที่ยังไม่ได้แก้สถานะเป็นงานค้างทั้งหมด:

1. **อีเมลและสมาชิกจริง:** ยืนยันโดเมนผู้ส่ง/SMTP แล้วตรวจสมัคร ยืนยัน และส่งถึงผู้รับหลายบัญชีที่ยินยอม ทดสอบลิงก์หมดอายุ/หยุดรับ/ส่งล้มเหลว พร้อมเวลานำส่ง
2. **คนในพื้นที่และหลายบทบาท:** ทดลองกับชาวบ้าน/ตัวแทน/ผู้ดูแลหลายบัญชี โทรศัพท์จริง กลางแจ้ง และเน็ตสะดุด เพื่อดูว่าอ่านสถานการณ์ บันทึก ประสาน และปิดเหตุเองได้หรือไม่
3. **ข้อมูลและการเดินระบบ:** ตรวจช่วงข้อมูลขาด, นิยามช่วงเฉลี่ยฝุ่น/เวลาแต่ละแหล่ง, การแทน NRT ด้วย SP, ความเร็วเมื่อใช้พร้อมกัน และการกู้คืนข้อมูล แหล่งสถานีเพิ่มเติมต้องมีค่าจริง/เวลา/เงื่อนไขใช้งาน ไม่ใช้แปลง AQI แทน
4. **กล้อง:** เพิ่มเฉพาะภาพ/วิดีโอที่เปิดให้ใช้และตรวจพิกัด เวลา สิทธิ์ได้ รวมทดสอบว่ามองเห็นบริเวณป่าที่เกี่ยวข้องจริง ปัจจุบันกล้องสาธารณะในเมืองไม่ได้ครอบคลุมทุกป่า
5. **แบบจำลองไฟลาม:** มี DSM และ GFS แล้ว แต่ยังขาดชนิด/ปริมาณ/ความชื้นเชื้อเพลิงกับเหตุจริงตามเวลา ต้องทำ baseline และทดสอบอิสระก่อนแสดงอัตรา/ระยะ/ตำแหน่งไฟลามหรือความแม่นยำ EVI ไม่ใช่มวลเชื้อเพลิงโดยตรง
6. **พื้นที่เสียหาย/ผู้ประสานรายป่า:** ต้องมี polygon รอยไหม้และกระบวนการตรวจแก้ และรายชื่อที่ยืนยันขอบเขตการเผยแพร่ได้ ยังไม่ถือชุดขอบเขต RECOFTC เป็นข้อมูลเหล่านี้

ตรวจคลัง GFS เพิ่มในรอบนี้พบ **27 ไฟล์ไม่ซ้ำ**, เริ่มเก็บ **01:32 ICT** และรายการล่าสุดมีเวลาบันทึก **09:15/09:20/09:25 ICT** (104 cells/ไฟล์) สอดคล้องกับรอบที่ตั้งไว้ เป็นหลักฐานการเก็บเพิ่มหลัง release ก่อน ไม่ใช่คำรับรองว่าครบทุกชั่วโมงหรือมีประวัติ GFS เต็ม 180 วัน

จำนวน test ด้านซอฟต์แวร์ **321 cases** ไม่ใช่จำนวนคนทดลองหรือเปอร์เซ็นต์ความแม่นยำของระบบในพื้นที่
