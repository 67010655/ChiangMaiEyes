## ตรวจกล้องและแหล่งที่มา

- [AppServ PingRiver](https://appserv.net/pingriver.php) เผยแพร่ภาพนิ่งจากสถานีแม่น้ำปิง P.1, P.67, P.75, P.92 และ P.20; API ตรวจเวลาในชื่อไฟล์โดยตรง ไม่แปลงภาพเก่าให้ดูเหมือนสด
- [กล้อง อบจ.เชียงใหม่](https://chiangmaipao.go.th/all_cctv.php) มีรายการกล้อง แต่หน้าที่ตรวจแสดงสถานะ standby/waiting for feed จึงเก็บเป็นลิงก์ต้นทางเท่านั้น
- [รายการกล้องกรมทางหลวงภาคเหนือ](https://www.highwaytraffic.go.th/DOHMobile/Modules/CCTV2.aspx) ระบุกล้องทางหลวง 107 แม่แตงและ 108 เมืองเชียงใหม่; [หน้า 107](https://www.highwaytraffic.go.th/DOHMobile/Modules/InfoCamera.aspx?id=3126&direction=IN) และ [หน้า 108](https://www.highwaytraffic.go.th/DOHMobile/Modules/InfoCamera.aspx?id=3065&direction=IN) แสดงภาพ service-down ตอนตรวจ จึงไม่นับเป็น feed ที่ใช้ยืนยันเหตุได้
- [NASA FIRMS Area API](https://firms.modaps.eosdis.nasa.gov/api/area/) เป็นข้อมูลจุดตรวจจับไฟจากดาวเทียม; ใช้ [ตาราง availability ของ NASA](https://firms.modaps.eosdis.nasa.gov/api/data_availability/) เลือก VIIRS Standard Processing (SP) สำหรับข้อมูลย้อนหลังที่ NRT ไม่ครอบคลุม และ Near Real-Time (NRT) ในช่วงล่าสุด ผลนี้ไม่ใช่บัญชีเหตุไฟที่คนยืนยัน และ FIRMS ยังไม่ได้ให้ PM2.5 ลม หรือรายงานภาคสนาม

## งานที่ทำต่อได้เมื่อมีข้อมูลยืนยัน

1. ทดลองกับตัวแทนชุมชนและเจ้าหน้าที่หลายบัญชี: อ่านข้อมูล แจ้งควัน ยืนยัน/ปฏิเสธจุดดาวเทียม รับช่วง ประสานข้ามพื้นที่ ปิดเหตุ และทดสอบเน็ตหลุด/แจ้งซ้ำ โดยแยกข้อมูลซ้อมออกจากเหตุจริง
2. เก็บ ground truth อย่างมีเวลาและตำแหน่ง: พบไฟจริงแต่ดาวเทียมไม่พบ, จุดดาวเทียมที่ลงพื้นที่แล้วไม่พบไฟ, และกรณียังตรวจไม่ได้; เพิ่มค่าความคลาดเคลื่อนและที่มาผู้ยืนยันก่อนคำนวณผล
3. ตั้ง sender domain ที่มีสิทธิ์ DNS แล้วทดสอบสมัคร/ยืนยัน/แจ้งเตือนกับผู้รับที่ยินยอมและวัดเวลาส่งถึง
4. รักษาการเก็บข้อมูลตามรอบ และรัน backfill เมื่อ NASA อัปเดต availability/แทน NRT ด้วย SP; เทียบข้อมูลซ้ำข้ามดาวเทียมก่อนทำสถิติรวม ระบบต้องคงวันว่างเมื่อแหล่งต้นทางยังไม่มีข้อมูล
5. ตรวจการแทนที่ข้อมูล VIIRS NRT ด้วย Standard Processing เมื่อ NASA เผยแพร่รอบย้อนหลัง แล้วรัน backfill ซ้ำแบบ deduplicate โดยคงต้นทาง/เวลาสังเกต/เวลารับข้อมูล; ค่อยประเมิน MODIS และผลิตภัณฑ์พื้นที่ไหม้แยกจาก VIIRS เพราะชนิดข้อมูลและความละเอียดต่างกัน
6. เพิ่มกล้องได้เมื่อแหล่งเปิดภาพ/วิดีโอจริง พิกัด/เวลา/สิทธิ์เผยแพร่ตรวจสอบได้ และตรวจการหยุดอัปเดตแล้วเท่านั้น

รายการเหล่านี้เป็นเงื่อนไขด้านข้อมูล ความร่วมมือ หรือสิทธิ์ภายนอก ไม่ใช่ช่องโหว่ของ migration ที่ยังไม่ได้ deploy และไม่ควรแทนด้วยข้อมูลจำลองหรือบุคคลที่อนุมานจากแผนที่

## ข้อสรุป

งาน implementation ที่มีข้อมูลและสิทธิ์พร้อมในรอบนี้ถูก deploy และตรวจ API/UI production แล้ว งานที่ยังไม่ครบตามเกณฑ์แผนคือการใช้งานโดยชุมชนจริง การทดสอบอีเมลสมาชิกทั่วไป ความต่อเนื่องของคลังย้อนหลัง และการตรวจความแม่นยำด้วย ground truth—ต้องมีผู้ใช้/เหตุ/แหล่งข้อมูลจริงก่อนจึงจะปิดเกณฑ์ได้
