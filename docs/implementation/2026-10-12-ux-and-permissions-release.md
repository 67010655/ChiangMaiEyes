## งานที่เสร็จในรอบนี้

- หน้าหลักเรียงอำเภอตาม **จำนวนจุดดาวเทียมใน 24 ชั่วโมง** แทนคะแนนจากค่าคงที่เชื้อเพลิง ไม่ใช้ FRP ทำคะแนนสำรอง
- หน้าวิเคราะห์เก็บตัวเลือกฝุ่นและเวลาย้อนหลังไว้ในส่วนกดเปิด เพิ่มขนาดข้อความ กราฟ และปุ่ม ทั้ง Dark/Light
- ทดสอบหน้าจอมือถือที่ **CSS width 390 จริง** ไม่มีส่วนล้นแนวนอน และแก้ตำแหน่งปุ่มปิด/ช่องตัวเลือก
- หน้าที่ซ่อนไม่รับโฟกัส เปิดหน้าแล้วโฟกัสไปหัวข้อ Escape กลับหน้าหลักได้ หน้าต่างเข้าสู่ระบบ/รายงานกัก Tab และคืนโฟกัสปุ่มเดิม
- แก้การกด Escape ในหน้าต่างเข้าสู่ระบบให้ปิดเฉพาะหน้าต่างนั้น หน้าวิเคราะห์ด้านหลังยังเปิดอยู่
- หน้ารอโหลดใช้สีของธีม และหัวหน้าข้อมูลใช้พื้นทึบเพื่อไม่ให้เนื้อหาที่เลื่อนผ่านซ้อนกับหัวข้อ
- เขียนคู่มือ 10 หัวข้อใหม่ตามหน้าที่เว็บมีจริง แยกสถานี ดาวเทียม แบบจำลอง ช่วงรายงาน 24/72 ชั่วโมง และคลังวิเคราะห์ย้อนหลัง
- ตรวจภาพสุดท้ายพบ selector หัวหน้าข้อมูลไม่ตรงกับ HTML แก้เป็น `.rp-toolbar` และยืนยันสีพื้นทึบทั้งสองธีมจริง พร้อมแก้ข้อความนำและรายการแหล่งข้อมูลเก่าให้แยกขอบเขต RECOFTC, หมุดไฟ, AQI และ PM2.5
- รายละเอียดหมุดแยกภาพกรวยปลายลมออกจากระยะไฟลามที่ยืนยัน ไม่แสดงคะแนนกรวยเป็นดัชนีความเสี่ยงจริง

## แก้ความหมายของดัชนีรายอำเภอ

เดิมใช้ความชัน เชื้อเพลิง และความถี่ไฟรายอำเภอที่กำหนดไว้ในโค้ด รวมทั้งแทนความชื้นที่หายด้วย 50% จึงอาจสร้างอันดับที่ผู้ใช้เข้าใจว่าเป็นผลสำรวจ

รอบนี้ดัชนีรายอำเภอใช้ความแห้งของอากาศจากจุดอ้างอิงร่วม ไม่มีค่าคงที่เชื้อเพลิงหรือประวัติไฟรายอำเภอ ค่าหายหรืออากาศเก่าเกิน 3 ชั่วโมงไม่คำนวณเป็นคะแนน วันที่ตรวจพบอยู่ในอนาคตไม่ถือเป็นจุดล่าสุด

ดัชนีนี้ยังเป็นสูตรทดลอง ไม่ใช่โอกาสเกิดไฟหรือปริมาณเชื้อเพลิง ค่า 85/100 เมื่อพบจุดดาวเทียมเป็นเพียงเกณฑ์จัดลำดับทดลอง ประวัติจุดไม่ยืนยันว่าไฟดับหรือพื้นที่ฟื้นตัว

**ยังมีส่วนทดลองเดิม:** คะแนนหมอกควันรวมและภาพระยะลามยังมีค่าความชัน/เชื้อเพลิงสมมติ ระบุในหน้าจอแล้ว ส่วน `_localized_predictions` ของสามหมู่บ้านเป็นตัวอย่างที่ปิดด้วย `allow_prototype_data=false` ใน production ยังใช้เป็นหลักฐานพื้นที่ไม่ได้

## ตรวจสิทธิ์บน Supabase จริง

รัน [SQL ตรวจสิทธิ์](../../supabase/operations/20261012_audit_community_permissions.sql) บนโปรเจกต์ `zskizogquupkneubcayc` หลังทดสอบด้วย PGlite

- **17 เงื่อนไขผ่านทั้งหมด**: เจ้าของอ่าน/จัดการได้ คนละป่าที่ไม่เกี่ยวข้องอ่านไม่ได้ทั้ง RPC และ RLS ผู้รับเชิญอ่านได้แต่ยังบันทึกไม่ได้ ผู้รับร่วมประสานบันทึกได้แต่ไม่ได้สิทธิ์จัดการ ถอนสมาชิกแล้วเสียสิทธิ์ทันที และ metadata `role=admin` ยกสิทธิ์ไม่ได้
- ผู้ไม่ล็อกอินอ่านข้อมูลส่วนตัวหรือรับคิวอีเมลไม่ได้
- ใช้ตัวตนและเหตุสมมติในธุรกรรมที่ย้อนกลับทั้งหมด ผลยืนยันว่าเหลือ **ผู้ใช้/ป่า/เหตุซ้อม 0/0/0** ไม่มีรหัสผ่านหรือบัญชีทดสอบที่ใช้เข้าสู่ระบบสร้างค้างไว้
- ตรวจ HTTP ของเว็บจริง 7 จุดส่วนตัว ได้แก่ me, review queue, incidents, mail status, practice runs, field evaluation และ photos: ผู้ไม่ล็อกอินได้ **401 ทั้งหมด**

นี่เป็นการตรวจฐานข้อมูลและ API ยังไม่ใช่การทดลองกับชาวบ้านหลายบัญชีจริงหรือการทดสอบอัปโหลด/ดาวน์โหลดไฟล์ครบทุกเส้นทาง

## เชื่อม GFS PBL จริง

เพิ่ม `/api/ventilation?lead_hours=0|24|48` และส่วน “การระบายอากาศ · แบบจำลอง GFS” ในหน้าข้อมูล

- ใช้ GRIB2 ของ NOAA GFS 0.25°: HPBL หน่วย m, U/V ในชั้น PBL หน่วย m/s และ **VRATE ของ NOAA โดยตรง หน่วย m²/s** ไม่ใช้ PBL × ลม 10 เมตรแทน
- ตรวจผู้เผยแพร่ ระดับลม หน่วย รอบแบบจำลอง เวลาที่ข้อมูลแทน กริดเดียวกัน และพิกัด ก่อนแสดงผล ไม่เติมข้อมูลขาดเป็น 0
- ขยายกล่องคำขอออกถึงแนวกริดเพื่อรวมเซลล์ขอบจังหวัด ได้ **104 จุดกริด** รวมพื้นที่ข้างเคียง ค่าอ้างอิงหน้าจอเป็นกริดใกล้เมืองเชียงใหม่ ไม่ใช่ค่าเฉลี่ยทุกป่า
- ตรวจรายการไฟล์ที่ NOAA เผยแพร่จริง รอบที่มีชื่อโฟลเดอร์แต่ยังไม่มีไฟล์ใช้ไม่ได้ ระบบเลือกไฟล์จากรอบก่อนหน้าที่มี และแสดงสถานะนี้
- ecCodes ยังไม่รู้จักชื่อ/หน่วยรหัส HPBL ท้องถิ่นบางไฟล์ จึงผูกเฉพาะรหัส NCEP ที่ตรวจผู้เผยแพร่และตารางนิยามแล้ว ไม่เดาว่า parameter ที่ไม่รู้จักเป็น HPBL
- ติดตั้ง `eccodeslib` เพิ่มสำหรับ Linux หลังพบว่าตัวอ่านแบบไบนารีไม่อยู่ใน runtime Vercel และตรวจ API จริงซ้ำจนได้ข้อมูล
- เป็นข้อมูลแบบจำลองตามกริด ไม่ใช่การตรวจวัดในชุมชน ไม่มีการสอบเทียบของ ChiangMaiEyes และไม่ได้เชื่อมเป็นตัวตัดสินใจส่งอีเมลหรือสั่งการไฟ

นิยามตัวแปรและหน่วยอ้างอิง [NOAA GFS inventory](https://www.nco.ncep.noaa.gov/pmb/products/gfs/gfs.t00z.pgrb2.0p25.f000.shtml) และ [NCEP GRIB2 table 0.3](https://www.nco.ncep.noaa.gov/pmb/docs/grib2/grib2_doc/grib2_table4-2-0-3.shtml) การจัดเตรียมไลบรารีอ้างอิง [ECMWF ecCodes Python](https://github.com/ecmwf/eccodes-python)

## งานที่ยังต้องจบตามแผน

1. ทดสอบสมาชิก/ตัวแทนหลายบัญชีในหน้าเว็บจริง รวมรูปและรายงานครบเส้นทาง ขณะนี้ Browser ยังปฏิเสธสิทธิ์ไฟล์จากเว็บนี้ จึงไม่อ้างว่าทดสอบอัปโหลด/ดาวน์โหลดรอบนี้ผ่าน
2. อีเมลสมาชิกทั่วไปยังต้องมีโดเมนผู้ส่งและ SMTP ที่ยืนยัน ผู้ใช้ให้คงการทดสอบก่อน ยังไม่ได้ซื้อโดเมนหรือส่งอีเมลใหม่ในรอบนี้
3. ย้ายข้อมูล GFS ไปเก็บย้อนหลังแบบถาวรและเก็บตัวอย่างแต่ละ model run เพื่อวิจัย ตอนนี้เป็นการอ่านพร้อม cache ระยะสั้น ไม่ใช่คลัง GFS 180 วัน
4. แทนค่าสมมติที่เหลือด้วยข้อมูลภูมิประเทศ/เชื้อเพลิงและผลทดลองที่ตรวจต้นทางได้ ก่อนรับรองผลคาดการณ์ไฟลาม
5. ทดลองกับคนในพื้นที่และเก็บคู่ข้อมูลอิสระเพื่อประเมินความเข้าใจ ความแม่นยำ จุดพลาด/เตือนเกิน และความเร็วการใช้งาน ยังไม่มีผลความแม่นยำภาคสนามให้สรุป
