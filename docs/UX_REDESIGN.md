**ภาพรวมทั้งเว็บ**
- ข้อความใน HTML มีราว 71,500 ตัวอักษร ไม่นับ popup
- ประโยคปฏิเสธ: "ไม่ใช่" 44 ครั้ง, "ยังไม่" 27 ครั้ง
- ศัพท์เทคนิค: AQI 68, VIIRS 19, FIRMS 13, FRP 12, GFS 7, Open-Meteo 6 ครั้ง
- ฟอนต์ปน 9 ชุด (Space Grotesk, JetBrains Mono, Arial, Helvetica, Tahoma, Lucida ฯลฯ) และมี `font-family` 135 จุดใน index.html
- ภาษาไทยไม่มีฟอนต์ที่กำหนดไว้ จึงขึ้นตามเครื่องของแต่ละคน
- **ความต่างสี (contrast) ส่วนใหญ่ผ่าน:** ข้อความรอง 6.1:1, ปุ่ม 1362 4.8:1, ปุ่มดูไฟรอบตัวฉัน 5.2:1

## กฎที่ห้ามทำลาย (Codex ต้องรักษา)
1. **ย้ายคำเตือน ไม่ลบ** ทุกตัวเลขต้องมีที่มาในแตะเดียว ผ่านปุ่ม ⓘ หรือ "รายละเอียด"
2. **ไม่เรียกจุดความร้อนว่าไฟที่ยืนยันแล้ว** และข้อมูลเก่าต้องดูเก่า (สีเทาหรือจาง)
3. **ไม่แสดงระดับเชื้อเพลิงที่ไม่มีแหล่งรองรับ** ระยะลามแสดงเฉพาะจุดอายุไม่เกิน 24 ชม. พร้อมคำว่า "ถ้ายังไหม้อยู่"
4. **เทสต์ที่คุมกฎเหล่านี้ต้องผ่านทุกครั้ง** ห้ามแก้เทสต์ให้หลวมลง: `landContext.test.ts`, `popupPresentation.test.ts`, `spreadHint.test.ts`, `publicGuidance.test.ts`, `navigationUi.test.ts`, `lineLink.test.ts`, `liveRefresh.test.ts`
5. **ทุกครั้งที่ปล่อย** เปิดแท็บใหม่บนเว็บที่ build แล้ว คอนโซลต้องไม่มี error เพราะสคริปต์ใน index.html ถ้าล้มจะทำให้ทั้งหน้าค้าง

### F — พื้นฐาน (ทำก่อน เพราะทุกหน้าใช้ร่วมกัน)

**F1 ฟอนต์: Poppins + Aktiv Grotesk Thai** ⛔ รอเจ้าของงานเลือกช่องทางลิขสิทธิ์ (D4)
- **ปัญหา:** ฟอนต์ปน 9 ชุด, `font-family` 135 จุด, ภาษาไทยไม่ได้กำหนดฟอนต์
- **แก้:**
  - ใช้ stack `--font: 'Poppins','Aktiv Grotesk Thai',sans-serif` Poppins ไม่มีตัวไทย อักษรอังกฤษกับตัวเลขจึงมาจาก Poppins และภาษาไทยตกไปที่ Aktiv Grotesk Thai
  - ตัวเลขใช้ `font-variant-numeric: tabular-nums` แทน JetBrains Mono
  - โหลดเฉพาะน้ำหนัก 400 / 500 / 600 / 700 และใช้ `font-display: swap`
- **ต้องไล่เปลี่ยนให้ครบ:**
  - `--disp`, `--mono`
  - `.leaflet-popup-content` (บรรทัด 657)
  - `.paper` (หน้ารายงาน PDF), `.td-*` (มุมมอง 3D)
  - กราฟ SVG ที่มี `font-family="JetBrains Mono"` (บรรทัด 3680–3733)
  - wrapper ของ popup 3D ที่ใส่ mono แบบ inline
  - Arial, Helvetica, Tahoma, Lucida ที่ฝังอยู่ใน style
- **ห้าม:** โหลดไฟล์ฟอนต์จากเว็บแจกฟรีที่ไม่มีที่มา ต้องใช้ Adobe Fonts (web project) หรือไฟล์ที่ซื้อสิทธิ์จาก Dalton Maag เท่านั้น
- **ตรวจรับ:**
  - `grep -E "Space Grotesk|JetBrains|Arial|Helvetica|Tahoma|Lucida"` ใน frontend ต้องไม่เจอ
  - `CmeUxAudit` ต้องได้ `mono = 0` ทุกหน้า
  - ภาพหน้าจอวรรณยุกต์ไทยต้องไม่ชนกัน
- **ไฟล์:** index.html, public/*.css, public/*.js

**F2 ขนาดตัวอักษรขั้นต่ำและสเกล**
- **ปัญหา:**
  - คำระดับฝุ่น "ดี" เล็กสุดในจอที่ 9.9 px
  - บรรทัดความหมายใต้ตัวเลขในการ์ด 11 px
  - หน้ากล้องสาธารณะ 10 px
  - ย่อหน้าในหน้าวิเคราะห์ 13 px
- **แก้:**
  - ขั้นต่ำ 12 px ทุกที่
  - ข้อความรอง 14 px, เนื้อความ 16 px, หัวข้อ 18 / 20 / 24 px
  - ภาษาไทยใช้ line-height 1.6
- **ตรวจรับ:** `CmeUxAudit.scope().tiny` ต้องว่างในทุกหน้า
- **ไฟล์:** home-simple.css, ux-clarity.css, index.html

**F3 ชุดสีความหมายเดียวทั้งเว็บ**
- **แก้:**
  - แดง = จุดความร้อนใหม่, ส้ม = เฝ้าระวัง, เขียว = ปกติ, เทา = เก่า
  - ระดับฝุ่นใช้สีตามประกาศ คพ. 2566
  - ประกาศเป็น CSS token ชุดเดียว แทน hex ที่กระจายอยู่
- **ตรวจรับ:** สีระดับฝุ่นในการ์ด แผนที่ และ popup ต้องตรงกัน
- **ไฟล์:** index.html, *.css

**F4 ชิ้นส่วนกลาง**
- **ชิป ⓘ ที่มา:** แตะแล้วเห็นแหล่งข้อมูล เวลา และข้อจำกัด ใช้แทนบรรทัดเตือนยาว
- **ชิประดับ:** สี + ไอคอน + คำเดียว
- **empty state:** บอกว่าคืออะไร + ทำไมว่าง + ปุ่มทำต่อ
- **toast และข้อความผิดพลาดภาษาไทย:** แทน validation ภาษาอังกฤษของเบราว์เซอร์
- **หัว sheet:** มีปุ่ม ✕ และ handle ลากเลื่อน
- **ตรวจรับ:** ทุกหน้าใช้ชิ้นส่วนชุดเดียวกัน ข้อความ "ไม่ใช่" / "ยังไม่" บนจอแรกลดลงอย่างน้อยครึ่งหนึ่ง

### H — หน้าแรกและแผนที่ (เกณฑ์ข้อ 1–3)

**H1 การ์ดฝุ่น**
- **ปัญหา:** คำระดับเล็กสุดในการ์ด (9.9 px)
- **แก้:** แสดงคำระดับใหญ่ที่สุด (20 px) ในชิปสีตาม คพ. พร้อมไอคอนหน้า ตัวเลข µg/m³ เป็นบรรทัดรอง
- **ตรวจรับ:** ฟอนต์ของคำระดับ ≥ 18 px
- **ไฟล์:** index.html (`updatePublicBrief`), home-simple.css

**H2 บรรทัดความหมายใต้ตัวเลข**
- **ปัญหา:** 11 px
- **แก้:** 13–14 px ส่วนที่มา (Air4Thai / เวลา) ย้ายไปในชิป ⓘ
- **ไฟล์:** home-simple.css

**H3 แท็บเล็ต/คอมพิวเตอร์ไม่มีปุ่มชั้นข้อมูล**
- **ปัญหา:** ที่ 1024 และ 1280 px โหมดสาธารณะไม่มีทางเข้าปุ่มใหญ่ 4 อันเลย ต้องกดลิงก์เล็ก "ดูข้อมูลละเอียด" ก่อน
- **แก้:** แสดงปุ่มชั้นข้อมูลทุกขนาดจอ เปิดแผงเดียวกับมือถือ
- **ตรวจรับ:** `#mobileLayersBtn` หรือปุ่มใหม่มองเห็นได้ที่ 1024 และ 1280 px
- **ไฟล์:** index.html, home-simple.css

**H4 ช่องค้นหา**
- **ปัญหา:** พิมพ์แล้วไม่มีรายการแนะนำ และค้นหาไม่เจอก็ไม่มีข้อความบอก
- **แก้:**
  - ทำ autocomplete ค้นได้ทั้งอำเภอ ตำบล และป่าชุมชน
  - ถ้าไม่พบ ขึ้นว่า "ไม่พบ 'xxx' · ลองชื่ออำเภอหรือตำบล"
- **ตรวจรับ:** พิมพ์ "แม่ริม" ต้องเห็นรายการ, พิมพ์ "zzzz" ต้องเห็นข้อความไม่พบ
- **ไฟล์:** index.html (search)

**H5 popup ถูกการ์ดด้านบนบัง**
- **ปัญหา:** หัว popup ของอำเภอซ่อนอยู่ใต้การ์ดสรุป
- **แก้:** ตั้ง `autoPanPaddingTopLeft` ให้เท่ากับความสูง header + การ์ด ใช้กับทุก bindPopup
- **ตรวจรับ:** หัว popup ทุกชนิดอยู่ใต้การ์ด ไม่ถูกบัง
- **ไฟล์:** index.html

**H6 ป่าชุมชน 677 จุดรกแผนที่**
- **แก้:** ใช้ cluster ที่ zoom ต่ำ หรือแสดงเฉพาะขอบเขตเมื่อ zoom ≥ 11
- **ตรวจรับ:** ที่ zoom 9 มีหมุดป่าบนจอไม่เกิน 30
- **ไฟล์:** index.html (`renderForestMarkers`)

**H7 หมุดจุดความร้อน**
- **ปัญหา:** ขนาดและสีของหมุดแปรตาม FRP ซึ่งคนทั่วไปไม่รู้จัก
- **แก้:** ใช้ขนาดเดียว แยกแค่ใหม่ (กะพริบ) กับเก่า (จาง) ให้ตรงกับคำอธิบายสัญลักษณ์ ส่วน FRP เหลือในโหมดผู้เชี่ยวชาญ
- **ตรวจรับ:** คำอธิบายสัญลักษณ์ตรงกับหมุดจริง และไม่มีการกะพริบเมื่อเปิด reduced motion
- **ไฟล์:** index.html (`renderHotspots`)

**H8 หัวเว็บ**
- **ปัญหา:** นาฬิกาเดินทุกวินาทีแบบ monospace พร้อม "ICT"
- **แก้:** เหลือ "● มีข้อมูล · อัปเดต N นาทีที่แล้ว" อย่างเดียว
- **ไฟล์:** index.html (`tick`), CSS

**H9 ปุ่มควบคุมแผนที่ที่เป็นภาษาอังกฤษ**
- **ปัญหา:** "Zoom in", "Zoom out", "Drag to rotate map…" ทั้งใน Leaflet และ MapLibre
- **แก้:** เปลี่ยน title และ aria เป็นภาษาไทย
- **ไฟล์:** index.html

**H10 แผนที่โหมดสว่าง**
- **ปัญหา:** ชื่อหมู่บ้านเยอะจนรก
- **แก้:** ใช้ basemap สีอ่อนที่มีป้ายชื่อน้อยกว่า
- **ไฟล์:** index.html (basemap)

### M — popup และแผงรายละเอียด

- **ปัญหา:** เป็น `div` ที่กดได้แต่ focus ไม่ได้
- **แก้:** เปลี่ยนเป็น `<button aria-pressed>` หรือ switch
- **ไฟล์:** index.html

**L2 กราฟในแผงสรุปอากาศไม่มีข้อสรุป**
- **แก้:** ทุกกราฟมีประโยคสรุป 1 บรรทัด เช่น "7 วันนี้จุดความร้อนเพิ่มขึ้น"
- **ไฟล์:** index.html (charts)

**L3 empty state ของรายละเอียดจุด**
- **ปัญหา:** ข้อความ "คลิกจุด hotspot บนแผนที่" ปนภาษาอังกฤษ
- **แก้:** "แตะหมุดบนแผนที่เพื่อดูรายละเอียด" พร้อมไอคอน
- **ไฟล์:** index.html

### A — วิเคราะห์ / ข้อมูลในพื้นที่ / รายงาน

**A1 หน้าวิเคราะห์**
- **ปัญหา:**
  - กราฟแรกอยู่ลึก ~2,100 px (เลื่อน 2.6 หน้าจอ)
  - มีหัวข้อวิจัย 13 หัวข้อ
  - เปิดทุกหัวข้อแล้วได้ 41,177 ตัวอักษร
- **แก้:**
  - ส่วนบนเหลือการ์ด 3 ใบ: จุดความร้อน 30 วัน, ฝุ่น 7 วัน, อำเภอที่มีจุดมากสุด แต่ละใบมีประโยคสรุป 1 ประโยค
  - งานวิจัยทั้งหมดรวมไว้ใต้หัวข้อ "สำหรับผู้เชี่ยวชาญ" ที่ปิดไว้ตั้งต้น
  - บรรทัดเวลา/คำขอ VIIRS ย้ายไปในชิป ⓘ
- **ตรวจรับ:** กราฟแรกอยู่ในจอแรก (top < 812 px ที่ 375 px), จอแรก ≤ 300 ตัวอักษร
- **ไฟล์:** index.html (`#analytics`), ux-clarity.js

**A2 ย่อหน้ากว้าง 1,152 px ที่ 13 px**
- **แก้:** `max-width: 68ch` และ 16 px
- **ตรวจรับ:** ทุกย่อหน้า ≤ 720 px ที่จอ 1280 px

**A3 ข้อความผิดพลาดภาษาอังกฤษ**
- **ปัญหา:** ปุ่ม "จำลองตามข้อมูลนี้" ขึ้นข้อความของเบราว์เซอร์ว่า "Please select an item in the list."
- **แก้:** ข้อความผิดพลาดภาษาไทยข้างช่องที่กรอก
- **ไฟล์:** spread-workspace.js, index.html

**A4 ตัวเลือกป่าชุมชนเป็น select ธรรมดา 678 ตัวเลือก** (หน้าข้อมูลในพื้นที่ และหน้ารายงาน)
- **แก้:** เปลี่ยนเป็นช่องค้นหาที่พิมพ์ชื่อป่าหรืออำเภอแล้วกรองได้ ศัพท์ DSM, พิกเซล, GFS เปลี่ยนเป็นคำง่าย + ชิป ⓘ
- **ไฟล์:** index.html, terrain-ui.js, ventilation-ui.js

**A5 หน้ารายงาน**
- **ปัญหา:**
  - checkbox 20×20 px
  - ติ๊ก "รายละเอียดทุกจุด" แล้วเพิ่ม 18,863 ตัวอักษร
  - ชื่อแหล่งข้อมูลเป็นอังกฤษ (Disaster STAC, API Gateway, AWS)
- **แก้:**
  - ทำแถว checkbox ให้กดได้ 44 px
  - บอกจำนวนหน้าก่อนติ๊ก "รายละเอียดทุกจุด"
  - เปลี่ยนชื่อแหล่งข้อมูลเป็นภาษาไทย
- **ไฟล์:** index.html (`#reportview`, `.paper`)

### C — ป่าชุมชน / ตัวแทนป่า (เกณฑ์ข้อ 4–8)
หน้าหลัง login ตรวจจากโค้ดเท่านั้น ต้องมีบัญชีทดสอบบน localhost ก่อนถึงจะตรวจในเบราว์เซอร์ได้

**C1 ตอนยังไม่ login**
- **ปัญหา:** 3 จาก 4 แท็บขึ้นหน้า login เหมือนกันหมด
- **แก้:** แสดงการ์ดต้อนรับใบเดียว มีขั้นตอน 3 ขั้น: สมัคร → ขอสิทธิ์ป่า → รับแจ้งเตือน LINE ส่วนแท็บให้แสดงหลัง login (D3)
- **ไฟล์:** community-workspace.js

**C2 ข้อความยังพูดถึงอีเมล**
- **ปัญหา:** ยังเขียนว่า "ตั้งค่าอีเมล"
- **แก้:** เปลี่ยนเป็นการรับแจ้งเตือนทาง LINE
- **ไฟล์:** community-workspace.js

**C3 ข้อความแนะนำและฟอร์มเยอะ**
- **ปัญหา:** มี help paragraph 37 ย่อหน้า ฟอร์ม 8 ชุด และหน้ารายละเอียดเหตุมีฟอร์ม 5 ชุด
- **แก้:**
  - แต่ละสถานะของเหตุมีปุ่มหลักปุ่มเดียว
  - ใช้ชิปสถานะ
  - บันทึกเหตุแบบทีละขั้น (stepper) ให้เสร็จใน 1 นาที (เกณฑ์ข้อ 8)
- **ไฟล์:** community-workspace.js, field-checks.js

**C4 ช่องในฟอร์มแจ้งจุดความร้อนไม่มี label**
- **ปัญหา:** `reportLat`, `reportLng`, `reportDesc` (WCAG 3.3.2)
- **แก้:** ใส่ `<label>` ให้ครบ
- **ไฟล์:** index.html

**C5 คนทั่วไปกด "แจ้งไฟ" แล้วเจอหน้า login**
- **แก้:** เลือกแนวทาง (D5) ระหว่าง ให้ส่งพิกัดพร้อมเบอร์ 1362 โดยไม่ต้อง login หรือคงไว้แบบเดิมแต่บอกให้ชัดว่าต้องโทร 1362

### G — วิธีใช้และหน้าอื่น

**G1 หน้าวิธีใช้**
- **ปัญหา:** ข้อความย่อหน้ายาว 1,060 ตัวอักษร และหัวข้อ "References" เป็นภาษาอังกฤษ
- **แก้:**
  - ทำเป็นการ์ดภาพ 4 ใบ (ไอคอน + 1 ประโยค) ตามด้วยคำถามที่พบบ่อยแบบพับเก็บ
  - เปลี่ยนหัวข้อเป็น "แหล่งข้อมูล"
- **ไฟล์:** index.html (`#guideview`)

**G2 หน้ากล้องสาธารณะ**
- **ปัญหา:** ยังเข้าได้ผ่าน CmeNavigation ตัวอักษร 10 px ส่วนใหญ่เป็นกล้องวัดระดับน้ำ
- **แก้:** ลบทั้งหน้าหรือคงไว้ รอเจ้าของงานตัดสินใจ (D1)

## ยังไม่ได้ตรวจ
- หน้าป่าชุมชนหลัง login (ตรวจจากโค้ดเท่านั้น)
- ปุ่มบันทึกภาพ / ส่งออก PDF (ตรวจแค่ว่ามีตัวจัดการคำสั่ง ยังไม่ได้กดเพื่อดาวน์โหลด)
- หมุดรายงานจากผู้ใช้และหมุดเฝ้าระวังรายตำบล (ตอนตรวจมี 0 จุด)
- จอคอมพิวเตอร์ตรวจด้วยตัวเลขจากโค้ด ภาพจริงดูไม่ได้เพราะหน้าต่างพรีวิวแคบ
- มือถือจริงและ LINE in-app browser
- screen reader (VoiceOver / TalkBack)
