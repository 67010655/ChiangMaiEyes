ขอบเขตงานนี้: เกณฑ์เสร็จข้อ 1 และ 6 ของ PRODUCT_BRIEF และข้อรีวิว 15
(สื่อสารเชื้อเพลิงให้อ่านเข้าใจ) ไม่เปลี่ยนโมเดลไฟลาม ไม่ใช้ EVI และไม่คำนวณ

## ลำดับการเลือกข้อมูล

1. รหัส LDD ที่ชัดเจนซึ่งมากับจุดมีสิทธิ์ก่อนแผนที่ ตัวอย่าง A101 → นาข้าว
   แสดงข้อความ “น่าจะเป็นการเผาในแปลง ไม่ใช่ไฟป่า” พร้อมระบุว่าเป็นการประเมิน
   และยังไม่ยืนยันสาเหตุหรือการลามเข้าป่า A9xx ซึ่งเป็นเพาะเลี้ยงสัตว์น้ำไม่ถือเป็นการเผาพืช
2. รหัส F ใช้ชื่อไทยที่ระบุเต็งรัง/เบญจพรรณอย่างชัดเจนก่อน รหัส F201 เพียงอย่างเดียว
   ไม่ยืนยันเบญจพรรณ เพราะเอกสารแต่ละรุ่นใช้รายละเอียดต่างกัน ในตัวอย่างรหัสปี 2567
   หมายถึงป่าผลัดใบสมบูรณ์ ส่วน F202 ที่ไม่มีชื่อกำกับไม่ถูกเดาเป็นเต็งรัง
   ชื่อที่ระบุทั้งเต็งรังและเบญจพรรณใช้เพียงป่าผลัดใบ ไม่เลือกชนิดใดชนิดหนึ่ง
3. รหัสเขตการบริหาร เช่น NRF/CONSERVATION หรือรหัสหน่วยพื้นที่ผสม ไม่ใช้เป็นชนิดป่า
   ถ้าแปลรหัสไม่ได้ ใช้ ESA WorldCover ณ เซลล์นั้น พร้อมปีและแหล่งที่มา
4. ถ้า ESA ปี 2021 ระบุว่ามีต้นไม้ จึงเติมชนิดป่าจาก CGLS ปี 2019 ได้
   ไม่ใช้ป่าปี 2019 ทับพื้นที่เกษตร/ไม้พุ่ม/หญ้าจาก ESA ปี 2021
   ถ้า ESA ไม่มีเซลล์ที่ใช้ได้ จึงใช้ CGLS โดยบอกตรง ๆ ว่าเป็นชั้นปี 2019
5. ชั้นผลัดใบใบกว้างบอกได้เพียง “ป่าผลัดใบ (เช่น เต็งรัง/เบญจพรรณ)”
   ชั้น mixed forest ไม่ใช่หลักฐานว่าคือเบญจพรรณ และชั้นต้นไม้ไม่ใช่หลักฐานว่าปัจจุบัน
   มีเชื้อเพลิงแห้งหรือมีไฟป่า ทุกบรรทัดมี “ประเมินจากแผนที่ ไม่ใช่การสำรวจในพื้นที่”

ปีของแผนที่ต่างจากเวลาตรวจพบจุดความร้อน ไม่แสดงปีรับข้อมูลแทนปีสำรวจ
หาก GISTDA ไม่ระบุปีแผนที่ LDD ให้แสดงว่าต้นทางไม่ระบุ

## วิธีสร้างข้อมูลเชียงใหม่

ใช้ Python พร้อม dependencies สำหรับงาน offline ใน `scripts/requirements-terrain.txt`:

```powershell
backend/.venv/Scripts/python scripts/build_forest_landcover.py
```

สคริปต์ตรวจสิทธิ์จาก metadata API ก่อนดาวน์โหลด ตรวจ CRS EPSG:4326, dtype uint8,
หนึ่งแบนด์ และ nodata 255 ไม่อนุมาน CRS จากพิกัด ผลลัพธ์คงเซลล์ต้นฉบับ
0.000992063492 องศา (ผลิตภัณฑ์ nominal 100 ม.) ไม่มี interpolation
ตัด bounding box เชียงใหม่ 1578 × 2898 เซลล์ และ mask จุดกึ่งกลางเซลล์นอกขอบจังหวัด
เป็น nodata เก็บ `forest-landcover.bin.gz` กับ `forest-landcover.json` ใน `backend/app/data`.

ESA ที่ใช้ fallback เป็นไฟล์ `spread-landcover` เดิม: ข้อมูลต้นฉบับ 10 ม.
แต่ไฟล์ใน repo สุ่มใกล้สุดลงกริด 0.001 องศาโดย `scripts/build_spread_landcover.py`
จึงไม่อ้างว่าตำแหน่ง popup จำแนกพื้นที่ด้วยความละเอียด 10 ม.

สคริปต์สร้าง `community-forest-landcover.json` จากขอบเขตเดิมทั้ง 677 แห่ง:

- ใช้เฉพาะ geometry ที่ผ่านความถูกต้อง ไม่ซ่อมหรือเปลี่ยน boundary โดยเงียบ ๆ
- นับเซลล์ที่มีจุดกึ่งกลางภายใน Polygon/MultiPolygon และไม่อยู่ในรู polygon
- สัดส่วนถ่วงน้ำหนักพื้นที่เซลล์ด้วย cosine ของละติจูด ไม่ใช้พื้นที่ degree² เป็นตารางเมตร
- สัดส่วนเป็นร้อยละของตัวอย่างเซลล์ที่มีข้อมูล ไม่ใช่ร้อยละจากการรังวัดจริง
- 672 แห่งมีตัวอย่าง; ในจำนวนนี้ 663 แห่งมีชั้นป่าอย่างน้อยหนึ่งชนิด
  อีก 9 แห่งมีชั้นสิ่งปกคลุมประเภทอื่นตามแผนที่ปี 2019 จึงไม่สร้างชนิดป่าให้
- 4 แห่งไม่มีจุดกึ่งกลางเซลล์ที่ใช้ได้ และ 1 แห่งมี geometry ไม่ถูกต้อง คงรายชื่อไว้
  โดยเว้นชนิดป่า ไม่เติมค่าศูนย์หรือชนิดป่าจากจุดข้างเคียง
- Provider เติม `forest_types` และ `landcover_summary` จากไฟล์นี้ จำนวนป่ายังคง 677
  ตรวจ SHA-256 ของชุด boundary ก่อนใช้สัดส่วน ถ้าไฟล์เสริมหาย/เสียยังคืนทะเบียนป่าเดิมได้

## ตารางอ้างอิงไฟและเชื้อเพลิง

ข้อมูลต้นทางและหมายเลขหน้าอยู่ใน `backend/app/data/land-context-reference.json`
และสำเนาสาธารณะ `frontend/public/land-context-reference.json`.
ปรับเฉพาะตารางแล้วสร้างสำเนาใหม่ได้ด้วย:

```powershell
backend/.venv/Scripts/python scripts/build_forest_landcover.py --reference-only
```

ทุกแถวของชนิดไฟ ช่วงฤดู เชื้อเพลิง และระดับเชื้อเพลิงมี refs และลิงก์หน้า PDF
หน้า 72/75 ของเอกสารภาคเหนือใช้คำต่ำ/กลางกับ **ความรุนแรงไฟ** ไม่ใช่น้ำหนักเชื้อเพลิง
จึงไม่ใช้คำเหล่านั้นเป็นเกณฑ์แบ่งระดับเชื้อเพลิงจากชนิดป่า

**ช่องว่างหลักฐานที่ตั้งใจแสดง:** ยังไม่มีเกณฑ์อ้างอิงที่จัดทุก class เหล่านี้เป็น
เชื้อเพลิงต่ำ/กลาง/สูงจากแผนที่เพียงอย่างเดียว จึงแสดง “ยังจัดระดับต่ำ/กลาง/สูงไม่ได้”
แทนการสร้างเกณฑ์ใหม่ ไม่แสดงตัน/ไร่ ไม่เอาคาร์บอนที่สูญเสีย ความรุนแรงไฟ
EVI หรือสัดส่วนเรือนยอดมาแทนน้ำหนักเชื้อเพลิง นี่เป็นตารางบริบท ไม่ใช่ผลทำนายไฟลาม

## การต่อเว็บและขอบเขตการปล่อย

`GET /api/land-context` รับพิกัดและรหัส/ชื่อที่มากับจุด อ่าน raster ที่เก็บใน repo
ไม่มีการเรียกดาวเทียมหรือโมเดลภายนอกระหว่างเปิด popup และ runtime ไม่ต้องติดตั้ง GDAL
ฝั่งเว็บรวมคำขอ summary/details ของจุดเดียวกันและแสดง LDD เบื้องต้นได้เมื่อ API ไม่พร้อม
หากไม่มีหลักฐานชนิดพื้นที่จะคงสถานะไม่ทราบ แยกจากระบบติดต่อผู้ดูแล

ลำดับ popup 2D/3D และรายงานผู้ใช้: เวลา → ชนิดพื้นที่/ป่า → ผู้ควรประสาน →
รายละเอียดเพิ่มเติม (ตารางอ้างอิงและข้อมูลเทคนิค) คง 1362 ไว้ครั้งเดียว
การเปลี่ยนครั้งนี้ไม่ deploy, ไม่ apply migration และไม่เปลี่ยนการอนุมัติตัวแทน
