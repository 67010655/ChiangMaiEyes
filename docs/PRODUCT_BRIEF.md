## นิยามว่าเสร็จ: 8 ข้อที่ต้องผ่านกับผู้ใช้จริง (บนมือถือของเขาเอง ไม่มีคนช่วย)

คนทั่วไป (คนเชียงใหม่ 3 คนที่ไม่เคยใช้เว็บ แต่ละข้อภายใน 1 นาที)
1. บอกได้ว่าใกล้บ้านตัวเองมีไฟไหม และข้อมูลนั้นเก่าแค่ไหน
2. บอกได้ว่าฝุ่นวันนี้เป็นยังไง และค่านั้นมาจากไหน
3. รู้ว่าถ้าเห็นไฟต้องโทรหาใคร

ตัวแทนป่าชุมชน (จิตอาสาดอยปุย 2–3 คน)
4. login แล้วเห็นป่าของตัวเองเป็นหลัก
5. รู้ว่ามีจุดไฟ/ความเสี่ยงใกล้ป่าไหม และได้แจ้งเตือน (อีเมลหรือ LINE) เป็นภาษาคน
6. เห็นว่าไฟน่าจะลามไปทางไหน (ทิศ + ระยะคร่าว ๆ ระบุว่าเป็นค่าประมาณ)
7. รู้ว่าต้องติดต่อใคร (เขตรับผิดชอบ + ป่าที่เข้าถึงง่ายที่สุด + ช่องทางติดต่อ)
8. บันทึกเหตุหลังดับไฟเสร็จภายใน 1 นาที (ตำแหน่ง รูป ผล)

## ไม่ทำในรอบนี้
- กล้องสาธารณะ: ส่วนใหญ่เป็นกล้องวัดระดับน้ำ เอาออกจากหน้าหลักจนกว่าจะได้กล้องบนยอดไม้ของชุมชน
- พยากรณ์ไฟล่วงหน้า 30 วัน: ทำไม่ได้น่าเชื่อถือ ทำแค่พยากรณ์อากาศ 3–7 วัน
- Ranking ป่าชุมชน: ยังไม่มีข้อมูลบันทึกจริง และเสี่ยงให้คนแข่งกันเข้าพื้นที่อันตราย
- Machine learning: ยังไม่มีข้อมูลภาคสนามไว้สอน/วัดผล เก็บบันทึกเหตุให้ได้หนึ่งฤดูก่อน
- งานวิจัยเพิ่ม (hindcast, grid spread, LightGBM, Sentinel-2): พักไว้จนกว่าจะตอบข้อใดข้อหนึ่งใน 8 ข้อได้ตรง ๆ
- ศัพท์เทคนิคในหน้าแรก (FRP, VIIRS, FM1, รหัสจุด): ย้ายไป "รายละเอียดเพิ่มเติม" หรือหน้าวิเคราะห์

## วิธีทำงานและปล่อยเวอร์ชัน
1. ทุกงานใหม่ต้องตอบได้ว่าช่วยข้อไหนใน 8 ข้อ
2. Codex แก้โค้ด แล้ว commit + push ทุกครั้ง ไม่ปล่อยงานค้างใน working tree
3. Claude ทดสอบอิสระจาก commit นั้น (หลายขนาดจอ, backend ล่ม, วาดแผนที่พัง)
4. เจ้าของงานสั่งปล่อย: เลื่อน `main` ไปที่ commit นั้น แล้ว deploy ผ่าน CLI เท่านั้น (push ไม่ deploy เอง)
5. ตรวจเว็บจริงหลัง deploy และจด deployment ก่อนหน้าไว้ rollback
6. หลังแกนหลักเสร็จ ทดสอบกับผู้ใช้จริงตาม 8 ข้อบนมือถือของเขา (รวม LINE in-app browser)

## คำถามที่ต้องตัดสินใจ
- แจ้งเตือนป่าชุมชน: อีเมลพอไหม หรือต้องมี LINE ด้วย
- ใครอนุมัติสิทธิ์ตัวแทนป่า และตรวจอย่างไร
- ข้อมูลติดต่อหัวหน้าป่า: เก็บจากไหน และได้รับอนุญาตให้แสดงต่อสาธารณะไหม
- เหตุที่ชุมชนบันทึก แสดงให้คนทั่วไปเห็นแค่ไหน
- วันทดสอบกับจิตอาสาดอยปุยและคนเชียงใหม่ 3 คน (ก่อนเข้าฤดูไฟ ม.ค.)
